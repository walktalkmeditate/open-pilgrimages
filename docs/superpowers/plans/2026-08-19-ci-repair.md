# CI Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `npm run build-index` deterministic so the CI drift check can pass, and bring the workflow's actions off deprecated Node 20.

**Architecture:** `scripts/build-index.ts` currently stamps `generatedAt: new Date().toISOString()` unconditionally, so `git diff --exit-code index.json` always fails — all 20 recorded CI runs died there. Split the script into pure, testable functions (`scanRoutes`, `buildIndex`) plus a thin `main()` that does I/O. `buildIndex` takes the previous index and a clock function; when route data is unchanged it carries the old timestamp forward, so re-running is a true no-op.

**Tech Stack:** TypeScript, `tsx`, Node's built-in `node:test` runner, GitHub Actions.

## Global Constraints

- **No new npm dependencies.** Tests use built-in `node:test` and `node:assert/strict`, run through the already-installed `tsx`.
- **`generatedAt` stays required** by `schema/index.schema.json`. Do not remove the field.
- **Do not weaken the CI drift check.** `git diff --exit-code index.json` must remain in the workflow.
- **Do not modify anything under `routes/`.** This plan changes no route data.
- **Generated output must be deterministic across filesystems.** `readdirSync` order is not stable — macOS APFS returns entries alphabetically, Linux ext4 returns hash order. Anything derived from a directory listing must be explicitly sorted, or `index.json` generated locally will not match the same file regenerated on the CI runner and the drift check will fail there regardless of the timestamp fix.
- Schema version stays `"1.0.0"`.
- Commit messages follow the repo's conventional-commit style (`fix:`, `test:`, `ci:`, `refactor:`).

Change `scanVariants` to accept the root:

```ts
function scanVariants(routeDir: string, root: string): VariantEntry[] {
  const variantsDir = join(routeDir, "variants");
  if (!existsSync(variantsDir) || !statSync(variantsDir).isDirectory()) {
    return [];
  }

  const variants: VariantEntry[] = [];
  for (const entry of readdirSync(variantsDir)) {
    const varDir = join(variantsDir, entry);
    const metaPath = join(varDir, "metadata.json");
    if (!statSync(varDir).isDirectory() || !existsSync(metaPath)) continue;

    const meta = loadJson(metaPath);
    variants.push({
      id: meta.id,
      name: meta.name,
      distanceKm: meta.overview?.distanceKm ?? 0,
      path: relative(root, varDir),
    });
  }

  // readdirSync order is filesystem-dependent; sort so output is stable
  // between a developer's machine and the CI runner.
  return variants.sort((a, b) => a.id.localeCompare(b.id));
}
```

Add the exported `scanRoutes`, lifting the loop verbatim out of `main()`:

```ts
const REGION_BY_COUNTRY: Record<string, string> = {
  ES: "Europe", FR: "Europe", PT: "Europe", IT: "Europe", DE: "Europe",
  NO: "Europe", SE: "Europe", GB: "Europe",
  JP: "Asia", IN: "Asia", CN: "Asia", KR: "Asia", NP: "Asia",
  US: "Americas", MX: "Americas", CA: "Americas",
  IL: "Middle East", TR: "Middle East",
};

export function scanRoutes(routesDir: string, root: string): RouteEntry[] {
  const routes: RouteEntry[] = [];

  for (const entry of readdirSync(routesDir)) {
    const routeDir = join(routesDir, entry);
    const metaPath = join(routeDir, "metadata.json");
    if (!statSync(routeDir).isDirectory() || !existsSync(metaPath)) continue;

    const meta = loadJson(metaPath);
    const countries: string[] = meta.overview?.countries ?? [];
    const primaryCountry =
      countries.length > 1 ? countries[countries.length - 1] : countries[0] ?? "";

    const routeEntry: RouteEntry = {
      id: meta.id,
      name: meta.name,
      region: REGION_BY_COUNTRY[primaryCountry] ?? "Other",
      country: primaryCountry,
      distanceKm: meta.overview?.distanceKm ?? 0,
      topology: meta.overview?.topology ?? "",
      tradition: meta.tradition?.type ?? "",
      path: relative(root, routeDir),
    };

    const variants = scanVariants(routeDir, root);
    if (variants.length > 0) {
      routeEntry.variants = variants;
    }

    routes.push(routeEntry);
  }

  return routes.sort((a, b) => a.id.localeCompare(b.id));
}
```

```ts
export interface RouteIndex {
  schemaVersion: string;
  generatedAt: string;
  routes: RouteEntry[];
}

const SCHEMA_VERSION = "1.0.0";

export function buildIndex(
  routesDir: string,
  previous: RouteIndex | null,
  now: () => string,
  root: string,
): RouteIndex {
  const routes = scanRoutes(routesDir, root);

  // Compare everything except the timestamp. Identical content keeps the old
  // stamp so re-running the generator is a genuine no-op and the CI drift
  // check has something stable to diff against.
  const content = JSON.stringify({ schemaVersion: SCHEMA_VERSION, routes });
  const previousContent =
    previous === null
      ? null
      : JSON.stringify({ schemaVersion: previous.schemaVersion, routes: previous.routes });

  return {
    schemaVersion: SCHEMA_VERSION,
    generatedAt: content === previousContent ? previous!.generatedAt : now(),
    routes,
  };
}
```

Replace `main()` and the bare `main();` call at the bottom of `scripts/build-index.ts`:

```ts
export function readPrevious(indexPath: string): RouteIndex | null {
  if (!existsSync(indexPath)) return null;
  try {
    return JSON.parse(readFileSync(indexPath, "utf-8")) as RouteIndex;
  } catch (error) {
    // Returning null keeps a corrupt file from hard-crashing the generator,
    // but staying silent would make the resulting spurious timestamp bump
    // untraceable — and a confusing timestamp-only CI diff is exactly the
    // failure this plan exists to remove.
    console.warn(`Could not read previous index at ${indexPath}, treating as absent:`, error);
    return null;
  }
}

function main() {
  const routesDir = join(ROOT, "routes");
  const indexPath = join(ROOT, "index.json");

  const index = buildIndex(
    routesDir,
    readPrevious(indexPath),
    () => new Date().toISOString(),
    ROOT,
  );

  writeFileSync(indexPath, JSON.stringify(index, null, 2) + "\n");
  console.log(`Generated index.json with ${index.routes.length} route(s)`);
  for (const r of index.routes) {
    const variantCount = r.variants?.length ?? 0;
    const variantNote = variantCount > 0 ? ` (${variantCount} variant(s))` : "";
    console.log(`  ${r.id}: ${r.distanceKm} km${variantNote}`);
  }
}

function resolveInvokedPath(argv1: string | undefined): string | null {
  if (!argv1) return null;
  try {
    return realpathSync(argv1);
  } catch {
    return null;
  }
}

if (import.meta.filename === resolveInvokedPath(process.argv[1])) {
  main();
}
```

Add `realpathSync` to the existing `fs` import.

**Why `realpathSync` and not a bare comparison.** Node's ESM loader resolves
symlinks when computing `import.meta.filename`, but `process.argv[1]` keeps the
path exactly as invoked. Reached through a symlinked directory the two differ,
the guard fails, and `main()` silently does not run — exit 0, no output, no
error, `index.json` never regenerated. Normalising the `argv[1]` side removes
that. Note that `fileURLToPath(import.meta.url)` does **not** fix it: that
resolves symlinks the same way `import.meta.filename` does, so it changes
nothing about the mismatch.
